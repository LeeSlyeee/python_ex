# 260122 데이터 연결.py 핵심 요약

이 문서는 `260122 데이터 연결.py` 스크립트에서 다루는 LangChain의 **Data Connection (데이터 연결)** 기능과 **RAG (검색 증강 생성)** 구현 프레임워크에 대한 내용을 정리한 요약본입니다.

---

## 1. 데이터 연결 (Data Connection) 핵심 개념

외부에 있는 방대한 데이터(PDF, 텍스트, 웹페이지 등)를 가져와서 LLM이 이해하고 답변할 수 있도록 만드는 과정입니다.

### ① 문서 로더 (Document Loaders)

비정형 데이터원으로부터 문서를 로드하는 도구입니다.

- **`PyPDFLoader`**: PDF 파일의 텍스트를 페이지 단위로 읽어와 `Document` 객체 리스트로 변환합니다.
- **주요 메서드**:
  - `load()`: 파일을 읽고 내부 내용을 객체화합니다.

### ② 임베딩 (Embeddings)

텍스트(단어/문장)를 인공지능이 계산하기 좋은 **숫자 리스트(벡터)**로 점수화하는 기술입니다.

- **OpenAIEmbeddings**: OpenAI 서버를 사용하여 고품질의 벡터를 생성합니다. (유료/고성능)
- **HuggingFaceEmbeddings**: 오픈소스 모델을 로컬 환경에서 사용하여 비용 없이 벡터를 생성합니다. (무료/중간성능)
- **핵심 특징**: 의미가 비슷한 문장일수록 벡터 간의 거리가 가깝게 계산됩니다.

### ③ 벡터 저장소 (Vector Stores)

임베딩을 통해 바뀐 숫자 데이터들을 저장하고, 검색하기 좋게 관리하는 데이터베이스입니다.

- **`FAISS` (Facebook AI Similarity Search)**: 수백만 개의 데이터 중에서도 질문과 가장 비슷한 데이터를 초고속으로 찾아주는 검색 엔진입니다.
- **활용 흐름**:
  1. 원본 문서 조각 추출
  2. 숫자(벡터)로 변환
  3. FAISS 저장소에 인덱싱

---

## 2. RAG (Retrieval-Augmented Generation) 구현 기술

LLM의 지식 한계를 극복하기 위해 **"외부 실전 데이터 검색 + 답변 생성"**을 결합한 방식입니다.

### ① 검색기 (Retriever)

벡터 저장소에서 사용자의 질문(Query)과 가장 연관성이 높은 문서 조각(Chunk)을 찾아오는 인터페이스입니다.

- `db.as_retriever()` 명령어를 통해 벡터 DB를 검색 가능하게 변환합니다.

### ② QA 체인 (RetrievalQA)

질문을 받고(Input) -> 관련 정보를 찾아오고(Retrieval) -> LLM이 답변하게(QA) 하는 모든 과정을 자동화한 '체인(Chain)'입니다.

- **구성 요소**:
  - `llm`: 답변을 생성하는 인공지능 모델 (예: GPT-4o-mini).
  - `chain_type`: 검색된 정보를 결합하는 방식. (보통 모든 조각을 합치는 `stuff` 사용)
  - `retriever`: 관련 정보를 찾아올 검색기.

---

## 3. 전체 워크플로우 (Workflow)

1. **로드**: `PyPDFLoader`로 PDF 문서 읽기
2. **저장**: 문서를 숫자 벡터로 바꿔서 `FAISS` DB에 저장
3. **연결**: `RetrievalQA`로 검색 엔진과 GPT 모델 결합
4. **활용**: 사용자가 질문하면 관련 내용을 근거로 GPT가 정확한 답변 생성

---

## 4. 실무 팁

- **온도 설정 (`temperature`)**: 지식 검색 기반의 Q&A에서는 사실 기반의 답변이 중요하므로 보통 `0`으로 설정합니다.
- **경고 무시**: 라이브러리 업데이트에 따른 경고 메시지는 `warnings.filterwarnings('ignore')`로 관리하여 가독성을 높입니다.
